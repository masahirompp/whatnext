# 一覧を専用の tmux サーバの中で動かし、attach をクライアントの切り替えにする

[ADR-0010](0010-workbench-lives-inside-whatnext.md) のうち、`Enter` で端末を子の `claude attach` に明け渡す仕組みと、端末のウィンドウを閉じたときの扱いを置き換える。
作業台の置き場所、キー、残した `claude attach` の扱い、作業台を終了で閉じることは ADR-0010 のままである。
サイクル5の開始時に決めた。

ADR-0010 の構成では、`Enter` のたびに whatnext が自分の端末を子に明け渡していた。
そのために、Node の内部 API への介入（working-with-ink スキル）、`stty` による端末の設定の保存と復元、子が主画面に残す行の後始末が要った。
tmux を別のものに替えても、言語を替えても、明け渡すという構図は残る。

一覧そのものを専用の tmux サーバのセッションの中で動かし、端末はそのサーバのクライアントにする。

- `whatnext` を実行すると、専用の tmux サーバ（`tmux -L <名前> -f <whatnext の設定>`、`TMUX` は外す）のセッション `list` の中で一覧を動かし、端末をそこにつなぐ。`list` がすでにあれば、新しく動かさずにそこにつなぐ。
- `Enter` では、クライアントをセッション `<id>`（中で `claude attach <id>` が動く）に切り替える（`switch-client`）。`ctrl+q l` と空のプロンプトの ← では `list` に切り替える。Ctrl+Z で `claude attach` が終わったときも `list` に戻す。Ink は端末を一度も手放さない。
- 端末のウィンドウを閉じても、tmux のクライアントが離れるだけで、whatnext は終了しない。一覧、作業台、残した `claude attach`、フックと OTel の受け口は動き続ける。次に `whatnext` を実行すると同じ一覧につながり、attach から戻ったときと同じに扱う（閉じたときに見ていたセッションを `Last attached` の組に出し、カーソルをそこに置く）。
- 別の端末でつながっているときに `whatnext` を実行すると、一覧は新しい端末に移り、前の端末のクライアントは離れてシェルに戻る。
- 終了の操作（確認つき）では、tmux サーバごと閉じ、何も残らない。
- 一覧のプロセスが異常終了したとき（`kill` した、落ちた）は、ADR-0010 と同じく、次の起動で、動いているものがある作業台を引き継ぐかを聞く。

## Considered Options

- **ADR-0010 の構成（明け渡し）のまま作り直す**：サイクル4で動いた実績があるが、明け渡しのための介入と後始末が残る。この ADR の構成が破綻したときの戻り先にする。
- **端末のウィンドウを閉じたら whatnext も終了する**（今の挙動を保つ）：クライアントが離れたことを検知して一覧だけを終わらせ、作業台は残す、という逆向きの作り込みが要る。閉じている間のフックも失う。
- **別の端末で起動したとき、両方の端末に同じ一覧を出す**：tmux は小さいほうの端末に大きさを揃えるので、大きい端末の表示が欠ける。片方で attach すると、もう片方も同じ画面に切り替わる。
- **別の端末で起動したとき、すでに開いていると示して終了する**：開いたまま忘れたウィンドウを探しに行くことになる。
- **開き直したとき、閉じたときに見ていたセッションの画面に戻る**：起動すれば一覧から始まるほうが、「まず何に手を付けるか」を見る順序に合う。同じ画面には `Enter` 1回で戻れ、残した `claude attach` なら待ちもない。
- **利用者の tmux の中で起動したときの入れ子を理由に退ける**：ADR-0010 の構成でも、専用サーバのクライアントは入れ子になっている。不具合の想定はない。

## Consequences

- `stty` による保存と復元と、Node の内部 API への介入が要らなくなる見込みである。
- 端末のウィンドウを閉じたあとも、whatnext のプロセスと作業台が見えないところで動き続ける。ADR-0010 が「閉じても作業台を残す」案を退けた理由（見えないところにシェルとプロセスが残る）を、ウィンドウを閉じた場合に限って受け入れる。終了すれば何も残らない。whatnext は書き込まず、メモリは終了で消えるので、[ADR-0002](0002-no-writes-no-persistent-state.md) の永続状態には当たらない。利用者が起動したものが終了していないだけで、常駐デーモンでもない。
- 保留と待ち先の関係は、端末のウィンドウを閉じても残り、終了で消える。
- フックを取りこぼすのは、whatnext を終了している間だけになる。
- `whatnext` をもう一度実行しても、2つ目の一覧は動かない。受け口のポートで二重起動を判定する処理は、別の版の whatnext が動いているときのためだけに残る。
- サイクル5で実機で確かめる。PRODUCT.md の Further Notes「端末の明け渡しを無くす構成」の「確かめること」のどれかが、この構成ではどう回避しても満たせないと分かったら、この ADR を superseded にし、ADR-0010 の構成に戻す。
