# 選んだビューと、attach した時刻、初めて見た時刻を状態のファイルに書く

[ADR-0016](0016-persist-holds-and-waits-in-a-state-file.md) は、状態のファイルに書くものを保留（理由を含む）と待ち先の関係の2つに限った。
リポジトリのビュー（[PRODUCT.md](../PRODUCT.md)「リポジトリのビュー」）のために、次の3つを足す。
サイクル8の完了条件を満たしたあとに、利用者の依頼で決めた（2026-10-25）。

- 選んだビュー（ラダーのビューかリポジトリのビューか）
- セッションごとの、whatnext から最後に attach した時刻
- セッションごとの、一覧に初めて出た時刻（初めて見た時刻。一度も attach していないセッションの並びに使う）

リポジトリのビューは、区切りの中を最後に attach した順に並べる。
利用者がラダーの並べ替えを使いづらいと感じた理由の1つは、行の位置が変わって目で探し直すことだった。
時刻をメモリにだけ持つと、whatnext を起動し直すたびに並びが変わり、同じことが起きる。
whatnext を起動し直すのは、終了したとき、版を上げたとき、異常終了したとき、OS を再起動したときで、版を上げる頻度が高い（ADR-0016 と同じ事情）。
ビューも、起動し直すたびにラダーのビューに戻ると、`g` を押し直す手間が毎回かかる。

そこで、次のようにする。

- 3つとも `state.json` に書く。時刻のキーは `sessionId` にする。
- `--json` から消えたセッションの時刻は、保留と同じ規則で外し、ファイルからも消す。`--json` を読めなかった回には外さない。
- ファイルの `version` を 2 に上げる。`version` が 1 のファイルは、保留と待ち先の関係を読み、ビューはラダーのビュー、時刻はないものとして読む。

## Considered Options

- **時刻は書かず、`--json` の `startedAt` で並べる**：`startedAt` は `claude -r` で再開すると更新されるので、並びが動く（[DESIGN.md](../DESIGN.md)「待機時間の取り方」）。最後に attach した順という意味も持たない。
- **時刻は書かず、会話記録の最後の利用者の指示の時刻で並べる**：whatnext の外での作業も拾える。ただ、セッションが自分でターンを進めても順は変わらないが、外部 watcher が起こしたセッションや `claude -p` で送った指示でも上がり、「利用者が触った順」からずれる。会話記録は一言と待機時間を補うためだけに読む方針（[ADR-0011](0011-fill-in-from-transcripts-when-hooks-are-missing.md)）にも合わない。
- **版を 1 のままにし、ビューと時刻を足すだけにする**：版 1 しか読めない whatnext は、知らない項目を無視して保留と待ち先の関係を読むので、古い版に戻しても注釈が残る。利用者は版を上げるほうを選んだ（2026-10-25）。
- **ビューは書かず、起動のたびにラダーのビューで開く**：ADR-0016 の「書くものを増やさない」を守れる。利用者がリポジトリのビューを主に使うなら、起動のたびに `g` を押すことになる。

## Consequences

- ADR-0016 の「ファイルの形を変えるときは、読めない版のファイルを空として扱い、移行を求めない」を、1 から 2 への変更に限って改める。版を上げただけで保留と待ち先の関係が消えると、ADR-0016 で引き継ぐと決めた注釈を失うため。
- 時刻はセッションごとに増えるが、`--json` から消えたら外すので、ファイルの大きさは並行するセッションの数に比例するだけである。
- whatnext の外で `claude attach` したことは時刻に入らない。外で作業したセッションは、区切りの中で上がらない。
- 版 2 のファイルを書いたあとに、版 1 しか読めない版の whatnext に戻すと、そのファイルを空として読み、保留と待ち先の関係を引き継がない。すでに出した版の読み方は変えられないので、戻す前にファイルを控える。

## 見直す条件

- リポジトリのビューをやめたとき。時刻とビューを書く理由がなくなる。
- Claude Code が、利用者が最後に操作した時刻を `--json` などの公式の口で出すようになったとき。

## サイクル9での改め（2026-10-26）

ラダーのビューをやめてビューが1つになったので（上の「見直す条件」の1つ目に近い）、ビューは書かない。attach した時刻と初めて見た時刻は、リポジトリの区切りの中の並びに使うので書き続ける（[DESIGN.md](../DESIGN.md)「状態のファイルに書くもの」）。
