# 起動された行の起動元を、OS のプロセス表から導く

スキルのスクリプトや stdio の MCP サーバが Bash から起動した `claude -p` は、`--json` に `interactive` の行として出る。しかし、どの行が起動したかは `--json` にない。
起動元が分からないまま行が増えると、利用者には起動した覚えのない行に見える。
そこで、`ps` のプロセス表で行の `pid` の祖先をたどり、最初に当たった `--json` の別の行を起動元とし、一覧では起動元の下に `(sub)` を添えて入れ子で並べる（[PRODUCT.md](../PRODUCT.md)「起動された行」）。
サイクル8の完了条件を満たしたあとに、利用者の依頼で決めた（2026-10-25、PR #236）。

[ADR-0008](0008-dependencies-and-contact-points-with-tmux.md) の次の2点を改める。

- **入力**：`--json`、フック、OTel に、OS のプロセス表を足す。`ps` は作業台の `⚙` ですでに使っている基本コマンドで、依存するコマンドは増えない。
- **段の決め方**：「段は `--json` だけで決める」を、「段は `--json` の値と、行どうしの関係（利用者が結んだ待ち先と、プロセス表から導く起動元）から決める」に改める。関係から導くのは待ちの段だけで、`--json` の値から決める段の規則は変えない。起動元は、待ち先と同じく、自分がレビュー待ちに当たり、起動された行が終わっていなければ待ちの段に入る。

状態は今までどおり `--json` からだけ読む（[ADR-0001](0001-read-state-only-from-agents-json.md)）。プロセス表から読むのは行どうしの関係で、セッションの状態ではない。
起動元の関係は状態のファイルに書かず、更新のたびに導き直す。起動された行は終わるとプロセスごと消えるので、引き継ぐ必要がない。

## Considered Options

- **起動された行を一覧から外す**：行が突然出て混乱することはなくなるが、利用者は「ほかの行がサブエージェントで何かしていると分かること自体は問題ない」とした（2026-10-25）。外すと、起動された行が権限待ちなどで止まっても見えなくなる。
- **利用者が `f` で待ち先として結ぶ**：仕組みを増やさずに済む。しかし起動された行は数秒から数分で消え、スキルによっては次々に起動するので、結ぶ手間が見合わない。結んだ関係を状態のファイルに書くことにもなる。
- **会話記録や環境変数から起動元を引く**：確かめていない。`--json` と同じく、Claude Code が公式に約束した口ではない。プロセスの親子は OS が保証する関係で、Claude Code の版に左右されにくい。

## Consequences

- stdio の MCP サーバは起動元の `claude` の子プロセスなので拾える。HTTP で待ち受ける MCP サーバや、常駐のデーモンを経由する起動は、祖先に起動元が出ないので拾えず、今までどおりトップレベルに `(tty)` で並ぶ。
- `--json` と `ps` は別の時点で読むので、その間に行が終わったり、`ps` が読めなかったりする。そのときは前回の関係をメモリの中で持ち越す（[DESIGN.md](../DESIGN.md)「起動元の引き方」）。その間に pid が再利用されると、無関係な行が起動された行になりうる。確率はとても低いので受け入れた（#245）。
- 今の Claude Code（2.1.310）では、起動元の `--bg` の行は、Bash ツールのバックグラウンドで起動した行が動いている間も `working` のままなので、起動元が待ちの段に入る経路は見つかっていない。規則は `--json` の振る舞いが変わったときの備えとして残した（#237、#242）。
