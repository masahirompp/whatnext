# whatnext の操作は `ctrl+q` のあとも ctrl を押したままの形にし、文字だけの形は作業台の tmux に残す

[ADR-0010](0010-workbench-lives-inside-whatnext.md) はキーの起点を `ctrl+q` の1つに決めた。サイクル6で、attach している間の whatnext の操作を足していく中で、続けて押すキーの形を決めた。

サイクル7で作業台を作業台の画面に改めたとき（[ADR-0014](0014-workbench-shows-in-a-screen-the-user-opens.md)）、`ctrl+q ctrl+q`（作業台の出し入れ）は割り当てをなくした。`w` は作業台を作る操作（一覧の `w`、`ctrl+q ctrl+w`）に明け渡し、待ち先は `f`（一覧の `f`、`ctrl+q ctrl+f`）に移した。以下の規則は変えない。「作業台の中」は、作業台の画面のことである。

- whatnext の操作は、`ctrl+q` のあとも ctrl を押したままの形（`^Q^L`、`^Q^Y`、`^Q^X` など）にする。キーの説明もこの形で出す。文字は一覧の同じ操作の文字にそろえる（「一覧の文字を、ctrl を押したまま `ctrl+q` のあとに押す」）。
- 文字だけの形（`^Q c`、`^Q x`、`^Q l` など）は、作業台の中の tmux の既定のキーに残す。tmux の既定の割り当てがない文字（`y`、`e`、`h`、`j`）だけは、文字だけでも同じ動作にしてよい（説明には載せない）。

## Considered Options

- **文字だけの形にそろえる**：tmux の prefix の既定とぶつかる。既定の割り当てがない小文字は `a b e g h j k u v y` だけで、`l`（直前のウィンドウ）、`x`（ペインを閉じる）、`n`（次のウィンドウ）、`w`（ウィンドウの選択）はふさがっている。ctrl を押したままの形は、既定の割り当てがほとんどない（`C-o`、`C-z` などだけ）。
- **説明を短くするために文字だけの形を載せる**：`^Q l` も `^Q^L` も4文字で、長さは変わらない。
- 一番よく使う出し入れが `ctrl+q ctrl+q` なので、続けて押すキーも ctrl を押したままになりやすい（サイクル5で `^Q^L` と押して戻らずに混乱した）。

## Consequences

- 作業台の中でも、whatnext の操作と tmux の既定のキーが両立する。作業台の出し方を変えても（サイクル7の作業台の画面）、この両立を保つ。
- whatnext の操作を足すときは、ctrl を押したままの形で、tmux の既定と Claude Code のキーに割り当てのない文字を選ぶ。
