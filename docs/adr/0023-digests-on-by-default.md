# ダイジェストを既定で有効にし、`--no-digest` で切る

[ADR-0022](0022-ship-a-digest-mod-for-launched-sessions.md) のうち、「オプトインにし、起動時のオプションで有効にする」を改める。
mod を配ること、置き場所と層、受け口との契約は ADR-0022 のままである。

`whatnext` を引数なしで開くと、`n` で起動するセッションにダイジェストの mod を付け、Goal の行と右の欄を出す。
`whatnext --no-digest` で開くと、mod を付けず、Goal の行も右の欄も出さない。
0.24 までの `--digest` は消し、知らないオプションとして扱う（終了コード 2）。

## 既定で有効にする理由

オプトインでは、`--digest` を付け忘れて開いた一覧から `n` で起動したセッションに、ダイジェストが付かない。
mod は `claude --bg` の起動時に `--plugin-dir` で付けるので、起動したあとのセッションには付けられない。
利用者は `--digest` を使ってみて、ダイジェストをほぼ必須の機能と判断した（2026-11-23、#381）。
付け忘れの損（そのセッションでは最後までダイジェストを見られない）が、既定で利用枠を使う損より大きい。

ADR-0022 がオプトインにした理由は3つあった。既定を逆にしても、それぞれ次のように扱える。

- **mod の API が早期公開版で、予告なく変わりうる**：切る手段（`--no-digest`）を残し、Claude Code の更新で mod が悪い壊れ方をしたときの逃げ道にする。mod が読み込まれない環境では、Goal の行と右の欄の中身が出ないだけで、一覧のほかの挙動は変わらない（ADR-0022「何に頼ることになるか」）。
- **`--digest` を付けなければ mod も API も使わない**：`--no-digest` を付ければ使わない、に変わる。「依存先のない環境でも本体が同じように動くこと」（ADR-0004 が守ろうとしたこと）は、`--no-digest` で保てる。「`claude` との接点はコマンド、フック、OTel、会話記録だけ」という見込みは、既定で崩れる（mod の API が加わる）。
- **利用枠**：`n` で起動したセッションは、既定でターンごとに Haiku を1回呼ぶ。npm で公開しているので、ほかの利用者が断れるように `--no-digest` を残し、README とリリースノートで知らせる。受け手の確かめ（一覧がダイジェストを受けていないときは呼ばない。DESIGN.md「ダイジェストの mod」）は変えない。

## 切る手段を起動時のオプションにする理由

切る手段は起動時のオプション `--no-digest` だけにし、環境変数では切らない。

- 逃げ道は `--help` で見つけられる必要がある。
- 公開の口を起動時のオプションの1か所に保つ（環境変数は内部のものと整理した。#368）。
- 環境変数は、意図しないところへ引き継がれる。0.24 では、一覧の役に `--digest` を伝える内部の変数 `WHATNEXT_DIGEST=1` が、`n` で起動したセッションのシェルに引き継がれ、そこから流した画面の通しが `--digest` で動いて落ちた（#362、#363）。切る設定が同じように引き継がれると、ダイジェストが出ない理由に気づきにくい。

内部では、起動の口が一覧の役に `WHATNEXT_DIGEST` を `1` か `0` でいつも明示して渡す（DESIGN.md「ダイジェストの mod」）。
起動の口は引数だけで有効かどうかを決め、環境の値を読まないので、引き継いだ値では切れも入りもしない。

## ダイジェストが有効な一覧への `--no-digest` は、つながずに断る

ダイジェストを有効にした一覧が動いているときに `whatnext --no-digest` を実行すると、その一覧につながずに、標準エラーに1行出して終了コード 1 で終わる（2026-11-24、利用者の判断。文言は PRODUCT.md「ダイジェスト」）。

`--no-digest` は、利用枠を断る手段であり、mod が壊れたときの逃げ道である。
黙ってつなぐと、利用者は切ったつもりのまま `n` でセッションを起動し、そのセッションには mod が付いてターンごとに Haiku を呼ぶ。
知らないオプションを無視せずに終了コード 2 で断る理由（打ち間違えた `--no-digest` が黙って効かない）と同じ損が、正しく打った `--no-digest` で起きる。
whatnext は同時に1つだけ動かすので、求められた設定で開くには、動いている一覧を終了してもらうしかない。文言でその手順を示す。

逆向き（`--no-digest` の一覧に引数なしでつなぐ）は、何も示さずにつなぐ（下の Considered Options）。
向きで扱いが違うのは、損が違うためである。有効な一覧に `--no-digest` でつなぐと、断ったはずの利用枠を使う。切れた一覧に引数なしでつないでも、ダイジェストが出ないだけで、切ったのは `--no-digest` を付けた本人である。

一覧がダイジェストを有効にして動いているかは、一覧が一覧のセッションのオプション `@wn_digest` に置き、起動の口が読む（DESIGN.md「ダイジェストの mod」）。
0.24 にあった `@wn_digest` を、置き場所をサーバ全体から一覧のセッションに変えて残した。

## Considered Options

- **オプトインのままにする**（ADR-0022）：付け忘れを救えない。
- **必須にして、切る手段をなくす**：mod の API が壊れたときの逃げ道と、利用枠を断る手段がなくなる。
- **環境変数で切る**：上の「切る手段を起動時のオプションにする理由」のとおり。
- **`--digest` をしばらく受け付けて何もしない**：採らなかった（2026-11-24、利用者の判断）。0.x で、破壊的な変更を予告なく行うと README に書いてある。受け付ける期間を設けると、消す時期をもう一度決めることになる。`--digest` を付けた alias は終了コード 2 と使い方の表示で気づけるので、リリースノートに外すよう書く。
- **動いている一覧とつなぐときの引数が違うときに知らせる**（0.24 のシナリオ 86 の向きを逆にし、`--no-digest` の一覧に引数なしでつないだら知らせる）：採らなかった（2026-11-24、利用者の判断）。0.24 の知らせは、`--digest` を付け忘れて開いた一覧に `--digest` でつないだ人を救うものだった。既定が逆になると、ダイジェストが切れているのは `--no-digest` を自分で付けた本人の一覧で、付け忘れを救う相手がほぼいない。逆にした知らせは、引数なしでつなぐたびに出る。
- **ダイジェストが有効な一覧に `--no-digest` でつなぎ、一覧の下に知らせる**（0.24 のシナリオ 86 と同じ形）：採らなかった（2026-11-24、利用者の判断）。つないだ時点で、`--no-digest` を求めた人の前に、ダイジェストが有効な一覧が開く。知らせを読む前に `n` を押せば、mod の付いたセッションが起動する。知らせは効いていないことを伝えるだけで、効かせるには結局、終了して開き直すことになる。
- **ダイジェストが有効な一覧に `--no-digest` でつないでも、何もしない**（この ADR の最初の形）：採らなかった（2026-11-24、レビューの指摘を受けた利用者の判断）。明示したオプションが黙って効かない。上の節のとおり。

## Consequences

- 0.24 から上げた利用者は、何もしなくても、`n` で起動するセッションがターンごとに Haiku を1回呼ぶようになる。版は minor を上げ、README とリリースノートで知らせる。一覧の中では知らせない（2026-11-24、利用者の判断）。
- 動いている一覧のダイジェストの有無は、つなぐときの引数で変わらない。変えるには、一覧を終了して開き直す。`--no-digest` の一覧に引数なしでつなぐと、何も示さずにつながる。ダイジェストが有効な一覧に `--no-digest` でつなごうとすると、断られる。
- 0.24 の `--digest` の一覧を動かしたまま版を上げた利用者が `whatnext --no-digest` を実行すると、断られる（0.24 がサーバ全体のオプションに置いた `@wn_digest` を読む）。`--digest` なしの 0.24 の一覧にはつながる。
- PRODUCT.md「全体」の「オプトインの機能を足すときは、起動時のオプションで有効にする」は、「既定で働く機能を切る手段も、起動時のオプションにする」を含む形に改める。
- `whatnext new`（#358）に mod を付けるかは、この決定の範囲に入れない。
- 見直す条件は ADR-0022 と同じ（mod の API が正式な公開になったとき、または大きく変わって追従の費用が見合わなくなったとき）。
