# 保留と待ち先の関係は、状態のファイルに書いて、起動し直しても引き継ぐ

[ADR-0002](0002-no-writes-no-persistent-state.md) の「何も書き込まず、永続状態を持たない」を、保留（理由を含む）と待ち先の関係の2つに限って改める。
ほかの値（フックや OTel で受けた値、会話記録から読んだ値、`↳ <名前> done` の表示、カーソルなど）は、今までどおりメモリにだけ持つ。
サイクル7のあとに、利用者の依頼で決めた（2026-10-02）。

サイクル8で、attach して作業したときに保留を解く規則をやめ、保留は `h` で理由を空にしたときだけ解くことにした（2026-10-06、PRODUCT.md の Out of Scope）。下の「whatnext から attach して作業したとき」と、作業したかを判断する案の記述は、決めた当時のものである。

保留と待ち先の関係は、利用者が付ける注釈である。
`--json` からも会話記録からも導けないので、whatnext を終了すると失われ、起動し直すたびに付け直すことになっていた。
保留は「今の数時間の段取り」として持ち越さなくてよいとしていたが、利用者は日をまたいで使っていた。
whatnext を起動し直すのは、終了したとき、版を上げたとき、異常終了したとき、OS を再起動したときで、版を上げる頻度が高い。

そこで、次のようにする。

- 保留と理由、待ち先の関係を、`${XDG_STATE_HOME:-~/.local/state}/whatnext/state.json` に書く。キーは `sessionId` にする。
- 起動したときに読み、保留か待ち先を変えるたびに書き直す。一時ファイルに書いてから置き換え、書きかけのファイルを残さない。
- `--json` から消えたセッションの保留と関係は、今までの規則のまま外し、ファイルからも消える。`--json` を読めなかった回には外さない（一時的な失敗で全部消えるのを避ける）。
- whatnext が止まっている間に、保留のセッションで作業しても（`claude attach` を直接使うなど）、起動し直したときに保留は解かない。保留が解けるのは、今までどおり whatnext から attach して作業したときと、`h` を押したときだけである。
- 待ち先がすべて終わったことを示す `↳ <名前> done` は持ち越さない。起動し直したあとは観測から導き直す。組の入れ子で関係は見える。
- 専用の tmux サーバを分けて動かすとき（`WHATNEXT_TMUX_SOCKET`）は、ファイルを `state-<ソケット名>.json` に分ける。確かめるために動かした whatnext が、利用者の保留を書き換えないようにする。

`sessionId` は、セッションを止めてから `claude respawn` で起こしても、attach で起こしても変わらなかった（2.1.287）。

## Considered Options

- **Claude Code の側に置く（セッションの名前に印を埋めるなど）**：`--bg` のセッションはターンを終えると名前が付け直され、名前を変える公式のコマンドもない。会話記録に書いたりセッションに送ったりするのは [ADR-0003](0003-no-input-injection-or-proxy-response.md) に反する。
- **専用の tmux サーバのオプションに置く**：一覧のプロセスが異常終了しても、サーバが残っていれば引き継げる。whatnext を終了すると `kill-server` するので、終了、版の上げ直し、OS の再起動では消え、利用者が求める場面のほとんどで効かない。
- **`~/.config/whatnext/`、`~/Library/Application Support/whatnext/`、`~/.claude/whatnext/` に置く**：`~/.config` は利用者が書く設定の置き場で、dotfiles に取り込まれやすい。`~/Library/Application Support` は macOS のアプリの流儀で、CLI の利用者が探しにくい。`~/.claude` は Claude Code の領域で、利用者の設定に触れない方針に合わない。`~/.local/state` は XDG Base Directory 仕様の状態の置き場で、Claude Code、`gh`、`mise` も使っている。
- **作業したかを判断するために、保存したときの状態（`state`、`status`）も持ち、起動したときに違えば保留を解く**：whatnext が止まっている間の作業を拾える。ただ、「作業した」の判定を会話記録の比較まで広げることになり、規則が重くなる。利用者は保留を残すほうを選んだ。

## Consequences

- whatnext を捨てると、このファイルが残る。消しても失うのは保留と待ち先の関係だけで、セッションには影響しない。
- [ADR-0002](0002-no-writes-no-persistent-state.md) のうち「whatnext はファイルにもどこにも書き込まない」と「データも設定も持たない」は、このファイルを除いて成り立つ。ファイルの形を変えるときは、読めない版のファイルを空として扱い、移行を求めない（ファイルに `version` を持つ）。
- 保留の組に、日をまたいで行が溜まりうる。保留した日時を出すなどの手当てが要るかは、使ってから判断する。

## 見直す条件

- Claude Code がセッションに利用者の注釈（タグなど）を付ける公式の口を持ったとき。
- `sessionId` が、起こし直しや Claude Code の更新で変わるようになったとき。
