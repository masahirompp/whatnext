# 一覧の外からセッションを起動するサブコマンド `whatnext new` を足す

`whatnext new <ディレクトリかリポジトリ名> <指示>` を足す。
一覧を開かずに、`n` で起動するセッションと同じもの（フック、OTel、ダイジェストの mod）を付けて `claude --bg -- <指示>` を起動し、`id` を標準出力に出して終わる。
端末も tmux も使わない（#358）。

## 足す理由

フックと OTel と mod が付くのは、一覧の `n` で起動したセッションだけだった。
素の `claude --bg` で起動したセッションは「外で起動したセッション」になり、一言は会話記録で補われるが、CTX は `-` で、ダイジェストも付かない。
設定は `claude --bg` の起動時に固定されるので、あとから付け直せない（PRODUCT.md の Out of Scope「外で起動したセッションに、attach のときに OTel を付け直すこと」）。

利用者には、Raycast の script から、作業ディレクトリと指示を渡してセッションを投げ、attach せずに放置し、あとで一覧で拾う場面がある（2026-11-23）。
この場面のために端末を開いて `n` を押す手間をなくす。
スマホから起動する口（#360）も、どの形になってもこのコマンドを呼ぶ。

## 受け口のポートの状態ごとに付けるもの

起動のたびに受け口のポート（`127.0.0.1:14318`）を `GET /v1/whatnext` で確かめ、付けるものを決める。

| ポートの状態 | 付けるもの |
|---|---|
| 一覧が動いている（`whatnext`） | フック、OTel、mod |
| 誰も使っていない（`free`） | フック、OTel、mod |
| ほかのプログラムが使っている（`other`） | なし。標準エラーに理由を1行出す |

- **`free` でも断らず、同じものを付ける**（2026-11-23、2026-11-24、利用者の判断）。利用者は一覧を止めていることが多く、その間に投げる場面が主である。フックは受け手がいなくても失敗せず（`curl … ; exit 0`）、OTel の送り手も止まらない。あとで一覧を開けば、次のターンから届く（実機、2.1.331、2026-11-24）。
- **`free` の間に終わったターンの CTX とダイジェストは出ない。** 受け手がいない間の OTel は失われ、再送されない。一覧を開いた時点の CTX は `-` で、次のターンから出る。一言は会話記録で補われる。1ターンで終わる「投げて放置」のセッションでは、一覧を止めている限り、素の `claude --bg` との差が出ない。この限界は受け入れる。
- **`other` で付けないのは、`n` と同じ理由である。** 付けると、そのセッションは生きている間、指示と最後の応答の全文を、ポートを使っているプログラムに送り続ける。断らずに起動するのは、投げた指示を失わないためである。
- **mod は、一覧が `--no-digest` かどうかを見ずに付ける**（2026-11-24、2026-11-25、利用者の判断）。mod は、一覧がダイジェストを受けている間だけ Haiku を呼ぶ（DESIGN.md「ダイジェストの mod」の受け手の確かめ）。`--no-digest` の一覧も、動いていない一覧も受けていないので、mod を付けても利用枠は使わない。付けておけば、あとで引数なしの一覧を開いたときに、次のターンからダイジェストが出る。mod は起動時にしか付けられないので、付けない側に倒すと、[ADR-0023](0023-digests-on-by-default.md) が避けた「付け忘れたセッションに、あとから付けられない」が起きる。
- **mod を付けずに起動する手段は置かない**（2026-11-25、利用者の判断）。`--no-digest` の役目のうち、利用枠を断ることは、受け手の確かめで満たされている。mod の API が変わって mod が壊れたときの逃げ道は、素の `claude --bg -- <指示>` である。

何を付けるかの判断は、一覧の `n` の判断と同じ場所（`src/cli/attachments.ts` の `decideAttachments`）に置く。
一覧は、受け口を自分で開けたときだけ付け、`--no-digest` では mod を付けない。この挙動は変えていない。

## whatnext 自身は、ネットワークの口を開かない

スマホなどの外から起動する口は、whatnext の外に置き、そこから `whatnext new` を呼ぶ（2026-11-22、利用者の判断）。
受け口は今までどおり `127.0.0.1` だけで開き、フックと OTel とダイジェストを受けるだけにする。
外から届く口を whatnext が持つと、認証と公開の範囲を whatnext が負うことになる。

claude のセッションを窓口にする案（claude の Bash から `whatnext new` を呼ぶ）も採らない。
sandbox の中では claude が claude を起動できないので、`CLAUDECODE=1` のときは断る（`whatnext` を断るのと同じ見分け方。#300）。

## `claude` に渡す環境から `WHATNEXT_*` を外す

claude のデーモンは、それを起こしたプロセスの環境を持ち続け、そのあとのすべての `--bg` のセッションに渡す（#363）。
`whatnext new` がデーモンを起こすと、テスト用のポートやソケット名（`WHATNEXT_PORT`、`WHATNEXT_TMUX_SOCKET`）が、利用者のすべてのセッションに残りうる。
セッションに渡す値は `--settings` の `env` で渡すので、環境からは外す（2026-11-24、利用者の判断）。

## Considered Options

- **設定だけを出すサブコマンド（`whatnext settings`）にし、`claude --bg` は利用者のスクリプトが呼ぶ**：採らなかった。受け口の占有の確かめと、mod を付けるかの判断が、利用者のスクリプトに漏れる。
- **`free` のときは断る**：採らなかった（2026-11-24、利用者の判断）。一覧を止めている間に投げる場面が主で、断ると使えない。
- **`free` のときは、一覧を裏で起こす**：採らなかった（同）。一覧は専用の tmux サーバの中で動き、利用者が開いて終了するものである（ADR-0012）。裏で起こすと、利用者が起動していない常駐物になる（ADR-0002）。
- **会話記録の usage で CTX を補う**：採らなかった（ADR-0011 のとおり）。
- **`free` のときは mod を付けない**（2026-11-23 の最初の決定）：改めた（2026-11-24、利用者の判断）。ダイジェストを既定で有効にし（ADR-0023）、mod に渡す環境を一覧なしで組めると分かったため（専用サーバのソケットのパスは、`TMUX_TMPDIR` の実パスと uid とソケット名で決まる）。
- **指示を省けるようにする**：採らなかった。指示のないセッションは、attach して指示を書くまで何もしない。投げて放置する用途に合わず、attach するなら `n` で足りる。
- **同じ名前のリポジトリが複数あるときに、どれかを選んで起動する**：採らなかった（2026-11-23、利用者の判断）。端末がないので選ばせられず、違うリポジトリで黙って起動すると、指示が違う場所で実行される。候補を出して断り、`owner/name` で呼び直してもらう。

## Consequences

- サブコマンドが2つになる（`workbench`、`new`）。`whatnext new` は、whatnext の起動の口のうち、端末も tmux も要らない唯一のものになる。
- セッションを `claude --bg` で起動する部品（引数の組み立て、出力の読み取り、ディレクトリの確かめ、`ghq list -p`）を、一覧の `n` と共有する（`src/ops/start.ts`）。起動のあと（attach するか、`id` を出して終わるか）と、信頼されていないときの扱い（信頼の確認を出すか、断るか）は、呼ぶ側が決める。
- 一覧が動いていないときに、mod に渡すソケットのパスを tmux に問い合わせずに組む。tmux がソケットを置く場所の決め方（`TMUX_TMPDIR` の実パスの下の `tmux-<uid>/<名前>`）に頼ることになる。呼ぶ側の `TMUX_TMPDIR` が、一覧を開く端末のものと違うと、mod は一覧を見つけられず、ダイジェストが出ない（フックと OTel は届く）。
- mod に渡す tmux の実行ファイルも、呼ぶ側の `PATH` と、よくある置き場所から探して絶対パスで渡す。ランチャーの `PATH` に tmux が無くてもダイジェストが出るようにするためである。どこにも見つからないときは、起動はして、標準エラーで知らせる。
- 「何も書き込まず、常駐物を持たない」（ADR-0002）は変わらない。`whatnext new` は起動してすぐ終わり、キューも状態も持たない。
- `--name`、待ち先の指定、`--json` の出力は持たない。使う場面が出たら足す。
