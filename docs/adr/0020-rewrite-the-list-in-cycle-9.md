# サイクル9で一覧を書き直す（サイクル8を最後のサイクルとした判断を覆す）

サイクル7の終わりに、サイクル8を最後のサイクルとし、本番品質で書き直して、`src/` とテストを消さずに通常の開発へ移ると決めた（#207。この判断は ADR にせず、PRODUCT.md「サイクル8の完了条件」と CLAUDE.md にだけ書いていた）。
サイクル8は完了条件を満たした（PRODUCT.md「サイクル8の完了条件」）。しかし、サイクル8の終わり（2026-10-25）に利用者の判断でこれを覆し、サイクル9を行うことにした（#270）。

理由は次の2つである。

- 一覧のセッションどうしの依存には2種類ある。プロセスの親子から導く依存（起動された行、`(sub)`）と、利用者が結ぶ依存（待ち先）である。この2つの仕様を、利用者が追えなくなった。規則が、ラダーのビューの組の位置、保留、`↳ <名前> done`、リポジトリのビューの区切りと掛け合わさって増えた（#235、#254、#263、#264）。
- 2種類の依存をリポジトリを跨いで組めることが、herdr や cmux との違いだと利用者は考えている（PRODUCT.md「近い道具との違い」）。違いの中心になる部分の理論が利用者の頭から離れたまま、通常の開発で積み上げたくない。

そこで、次のようにする。

- サイクル9で書き直すのは一覧の部分である。段と並び、画面の組み立て、操作、状態のファイル、cli がこれに当たる。作業台の制御（いまは操作のモジュールに一覧と混ざっている）も、仕様が収束しているので docs から書き直す。
- 末端の部品は、サイクル8の cycle-end で `lib/` に昇格し、書き直さない（昇格の ADR を参照）。サイクル9は、昇格したモジュールを契約の docs を通して使う。
- サイクル9も本番品質で書き直す（利用者の判断、2026-10-25）。品質の条件はサイクル9の完了条件に書く。サイクル9を最後のサイクルにするか（cycle-end で `src/` を残して通常の開発へ移るか）は、cycle-start で決める。
- 同じ日に、ラダーのビューをやめると決めた（#271、PRODUCT.md の Out of Scope）。段の判定（STATUS の列）は残す。名前は whatnext のまま変えない（#272）。

## Considered Options

- **通常の開発に移り、一覧のコードをその場で直す**（#207 のとおり）：書き直す費用はかからない。しかし、利用者が仕様を追えなくなったのは、コードが利用者の頭の中の理論から離れたためである。コードを起点に直しても理論は戻らない。依存の規則を docs で組み直し、docs から書き直すほうが、理論とコードをもう一度揃えられる。
- **全体を書き直す**：作業台、tmux の扱い、入力（`--json`、フック、OTel、会話記録）は、仕様が収束していて、実機で確かめた罠も多い。書き直しても得るものが少なく、確かめ直す費用が大きい。

## サイクル9の grilling で決めること

サイクル8の2回目の cycle-audit（#269）と棚卸しで、決まっていないと分かった論点である。cycle-start の grilling の材料にする。cycle-audit から持ち越した D（#263、#264）は、CLAUDE.md の規則どおり、サイクル9の完了条件に番号付きで書き出す。

1. **2種類の依存を1つの木に混ぜるか。** 今は、起動元から起動された行への辺を待ち先の関係に足し、同じ入れ子と待ちの段の規則で導く（DESIGN.md「起動元の引き方」）。注釈（待ち先、保留）を付けた行は起動された行にしない例外があり、注釈を外すと `(sub)` に戻って付け直せない（#254。案は、そのまま `(sub)` に戻す、次に起動元との関係が変わるまで普通の行のままにする、`f` と `h` で付け直せるようにする、の3つ）。
2. **起動された行が動いている間に起動元を待ちの段に入れる規則。** 今の Claude Code（2.1.310）では効く経路がない（#237、#242）。備えとして残すか外すか。
3. **待ち元が一覧に出ていない間の木**（D1、#263）。今は待ち先がトップレベルに並ぶ。削除の巻き込みは、サイクル7は `--json` にある子孫すべて、サイクル8は画面に見えている木だけを数える。対話セッションを待ち元にしたときの前提（PRODUCT.md「未確定の前提」）ともつながる。
4. **`(tty)` の行を待ち先や待ち元にできるか。** `id` がなく、削除も attach もできない。削除の巻き込みでは確認に並べないと決めた（#248）。
5. **リポジトリを跨ぐ木の置き場所。** 今は根（待ち元）のリポジトリの区切りに木ごと置く（シナリオ 64）。待ち先のリポジトリの区切りには何も出ないので、そちらを見ている利用者には見えない。ラダーのビューをやめると、これが唯一の見え方になる。
6. **`↳ <名前> done` の規則**（D2、#264）。`done` を出している待ち元に新しく待ち先を結んだとき、サイクル7は消し、サイクル8は消さずに名前が増える。起動された行のために待ちの段にいる間に隠すこと、起動し直したときに引き継がないことも合わせて決める。
7. **状態のファイルに残す関係。** 不正な関係（1つの待ち先を2つの待ち元が待つ、一周する）を読んだときの扱い。起動元の関係を書かない方針（[ADR-0019](0019-derive-spawned-rows-from-the-process-table.md)）を保つか。ラダーのビューをやめたので、[ADR-0018](0018-persist-view-and-attach-times-in-the-state-file.md) の `view` は書く理由がなくなりうる（ADR-0018「見直す条件」）。
8. **保留と待ち先の重なり。** 根を保留にすると木ごと移る規則は、ラダーのビューの `On hold` の組のためのものだった。保留の理由を、保留と切り離して行のメモとして扱う案もある（#231。Out of Scope の「人間の手入力のメモ」と衝突する）。
9. **リポジトリの区切りの根の決め方**（#246）。`.bare` 型の worktree の構成では根が `.bare` になり、submodule では根が `.git/modules/<sub>` の中になる。submodule を親の区切りに入れるか、自分の区切りにするかは見た目の決定なので、画面の例で決める。
10. **同じ段・同じ時刻の行の名前の順**（#269 の小さな差）。サイクル7は `localeCompare`、サイクル8は文字の符号の順で、大文字と小文字、日本語の名前で順が変わりうる。

## Consequences

- サイクル8の cycle-end では、昇格したモジュールとそのテストのほかの `src/` とテストを消す。PRODUCT.md「サイクル8の終わりの手順」（transition-check で通常の開発へ移る）は行わない。
- 「近い道具との違い」に挙げた、順位とその根拠の表示は、ラダーのビューをやめたので違いではなくなる。違いの中心は、2種類の依存をリポジトリを跨いで組めることに移る。サイクル9の grilling で、PRODUCT.md の Problem Statement、Solution、撤退判定の観点と合わせて見直す。

## cycle-start で決めたこと（2026-10-26）

上の論点は、サイクル9の cycle-start の grilling で次のように決めた。結果は [PRODUCT.md](../PRODUCT.md)「依存（待ち先と起動された行）」「メモ」「リポジトリの区切りと並び」と「サイクル9の完了条件」に書いた。

1. **混ぜない。** 起動された行は見せるだけの関係にし、待ちの段と `↳ <名前> done` は待ち先だけで決める。起動された行かどうかはプロセスの親子だけで決め、起動された行には待ち先もメモも付けない（#254 の例外をやめる）。利用者は `(sub)` の行を、動いていることの確認にだけ使っていた。
2. **外す。** 起動元を待ちの段に入れる規則はなくす。困った場面もなかった。
3. **D1**：`(tty)` の行は待ち元にできない（待ち先にはなれる）。待ち元が一覧から外れている状態が起きなくなる。
4. 3 のとおり。削除の巻き込みで `(tty)` の行を確認に並べないこと（#248）は変えない。
5. **根の区切りにだけ出す**（今のまま）。待ち先は、利用者が待ち元の作業の一部と見なしたものである。利用者はリポジトリを跨ぐ待ち先を日に数回結ぶ。
6. **D2**：新しく待ち先を結んだら `↳ <名前> done` を消す（サイクル7の挙動）。2 により、起動された行のために `done` を隠す規則はなくなる。`done` を引き継がないことは変えない。
7. 木にならない関係は結ばれていないものとして読み飛ばし、ファイルは利用者が変えるまで書き換えない。起動元の関係を書かない方針（ADR-0019）は保つ。`view` は書かない。
8. **保留をメモに改める**（#231）。`(on hold)` の印をやめ、キーを `e`（attach している間は `ctrl+q ctrl+e`）にし、メモは任意で、セッションが `--json` から消えるまで残す。Out of Scope の「人間の手入力のメモ」は、セッションから離れたメモに範囲を絞った。
9. `.bare` 型の構成では根を裸のリポジトリの親にする。submodule は親のリポジトリの区切りに入れる。見た目は実装で描いた画面で確かめる。
10. 人の読み方の順（`localeCompare`）にする。

あわせて、Problem Statement の中心を「組の関係を覚えておくこと」に移し、撤退判定の観点と「近い道具との違い」を書き換えた（Consequences の2つ目）。サイクル9を最後のサイクルにするかは、cycle-start ではなく、サイクル9の終わりの transition-check で決める（利用者の判断）。

grilling で新しく分かったこと：利用者は、会話の外で動く MCP サーバが `claude -p` で起動したセッションでオーケストレーションを日常的に行い、それらがトップレベルに出て探せないことに困っている。手がかりを調べることを完了条件に入れた。
