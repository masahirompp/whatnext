# 一覧に依存しない末端の部品を `lib/` に昇格する

サイクル9では一覧の部分だけを書き直す（[ADR-0020](0020-rewrite-the-list-in-cycle-9.md)）。
書き直さない部品を `src/` に残すと、使い捨て層の境界が崩れ、次のサイクルが旧コードを読んで流用し始める。
そこで、サイクル8の cycle-end で、一覧に依存しない末端の部品を `lib/` に昇格し、永続層として維持する（2026-10-25、利用者の承認）。

昇格したのは次の部品である。契約は [docs/lib/](../lib/README.md) にある。

- **入力**（`lib/input/`）：外部コマンドの口、`claude agents --json` と Usage の読み取り、フックと OTel の受け口、会話記録、補う値、プロセス表の読み取り。
- **tmux**（`lib/tmux/`）：専用の tmux サーバの設定と操作、claude の画面と作業台のセッション、Ghostty の分割。
- **段の判定**（`lib/tier/`）：`--json` の行から段を決め、重複を除く。
- **文字の幅と色**（`lib/text/`）。

選んだ基準は、仕様が収束していること、使い捨て層に依存しないこと、実機で確かめた罠が多く、書き直す費用が大きいことの3つである。
昇格の前に、昇格する部品にかかわる未決の振る舞い（#265〜#268、#262）を利用者が決め、docs とコードを揃えた。昇格したあとは、書き直しで確かめ直す機会がないため。

## 昇格しなかったもの

- **起動元の導き方**（`spawners`）：pid 由来の依存の解釈で、サイクル9で依存の規則と一緒に組み直す（ADR-0020 の論点1）。プロセス表を読む部分だけを昇格した。
- **場所の問い合わせ**（`git` と `gh`）：リポジトリの区切りの根の決め方が未決（#246、ADR-0020 の論点9）。
- **attach している間のキーの表**：一覧の操作（保留、待ち先、起動、停止）を並べた表で、一覧の操作が変わると変わる。tmux の設定は、キーの表を引数で受け取るように改めた。
- 段と並び、画面の組み立て、操作（一覧と作業台の制御）、状態のファイル、cli。

## 言語

PRODUCT.md「端末の明け渡しを無くす構成」は、言語を替える案（Rust）を「`lib/` に最初のモジュールを昇格させる前に判断する」としていた。
再検討の条件（今の構成が破綻する、claude の画面を whatnext の中で直接描く要件が出る）はどちらも起きていないので、Node（TypeScript）のまま昇格した（利用者の判断）。
昇格したことで、言語を替える費用は `lib/` の書き直しの分だけ増えた。

## Considered Options

- **何も昇格せず、サイクル9で全体を書き直す**：境界は保てるが、作業台、tmux、入力という収束した部分を確かめ直す費用がかかる。ADR-0020 の「一覧の部分だけを書き直す」とも合わない。
- **`src/` の一部を消さずに残す**：境界が崩れる（cycle-rewrite の規律）。
- **`tmux` を昇格しない**：tmux の部品の単体テストは設定とプロセス表の判定だけで、実機の確かめは画面の通し（消すテスト）にあった。昇格すると、サイクル9で画面の通しを作り直すまで、tmux の振る舞いはテストで守られない。利用者は、この費用を受け入れて昇格を選んだ。

## Consequences

- 依存は `src/` → `lib/` の一方向だけにする。`lib/` から `src/` を import しない。実装セッションは契約の docs を通して使い、中身のコードは読まない（CLAUDE.md「昇格済みモジュール」）。
- テストは各部品の横に置き、`src/` とテストを消しても残る。ビルドの出力は `dist/lib/` と `dist/src/` に分かれる。
- 昇格した部品の振る舞いを変えるときは、PRODUCT.md・DESIGN.md と契約の docs を先に直す。
- 会話記録の読み取りには、原因の分かっていない観察が2件ある（#253、#244）。昇格した部品の不具合と分かったら、そこで直す。
- 仕様が覆ったら、この ADR を遷移させ、その部品を使い捨て層に戻す。
