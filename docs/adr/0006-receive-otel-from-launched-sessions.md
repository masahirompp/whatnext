# whatnext が起動したセッションには OTel を付け、起動している間だけ受ける

whatnext が `n` で起動するセッションには、`claude --bg --settings '{"env":{...}}'` で OTel の設定を付け、送信先を whatnext が `127.0.0.1` で開く受け口にする。
whatnext は起動している間だけ受け口を開き、受けた値はメモリにだけ持つ。
値の使い道は、コンテキストの大きさ（CTX）の列、コスト（COST）の列、待機時間の推定の3つに限る。
段は引き続き `--json` だけで決める（[ADR-0001](0001-read-state-only-from-agents-json.md)）。

サイクル2で試行として入れ、利用者が使ったうえで本採用と判断した。

`--settings` を使うのは、起動したシェルの環境変数が `--bg` のセッションに届かず、プロジェクトの設定ファイルからは送信先を設定できないためである（[claude-code-behavior.md](../claude-code-behavior.md)）。
`--settings` はそのセッションの起動の引数で、利用者の設定ファイルは書き換えない。受けた値も閉じれば消えるので、[ADR-0002](0002-no-writes-no-persistent-state.md) の「何も書き込まず、永続状態を持たない」は守られる。

## Considered Options

- **外部のメトリクス基盤を属性プラグイン経由で読む**：当初の M3 の設計。利用者に常駐の基盤と設定を求める。[ADR-0005](0005-dependencies-and-contact-points.md) を参照。
- **外で起動したセッションを、次に attach するときに OTel を付けて起動し直す**：同じセッションのまま設定を足す手段がない。`claude respawn` はフラグを取らず、`--resume` に `--settings` を付けると別の ID のコピーが起動して元も残る。attach が「止めて複製する」という見えない副作用を持つ。
- **利用者の `~/.claude/settings.json` を書き換えて OTel を有効にする**：ADR-0002 に反する。

## Consequences

whatnext の外で起動したセッションと対話セッションは OTel を送らないので、CTX と COST は空欄になり、待機時間は観測から推定する。
User Story 12（経由せずに起動したセッションも一覧に出る）のうち、この3つだけは例外になる。
ADR-0002 は、statusline のタップを whatnext が起動したセッションにだけ付ける案を、外で起動したセッションが空欄になるとして退けていた。
この ADR ではその空欄を受け入れた。空欄になるのは付加的な値だけで、行と段は変わらないためである。
空欄が困るようになったら、利用者が自分で `~/.claude/settings.json` の `env` に OTel の設定を書く経路を検討する。これは ADR-0002 の「書き換えを求める別ツールも前提にしない」を緩める判断になる。

受け口のポートは固定なので、whatnext を2つ同時に開くと後から開いた方は受けられず、OTel なしで動く。
whatnext を開き直した直後は、止まっているセッションの待機時間は分からない（logs は再送されない）。
